The Nim Team is happy to announce version 2.2.14, the seventh patch release for our stable release, Nim 2.2.

It comes seven weeks after the 2.2.12 release and it contains [142 commits](https://github.com/nim-lang/Nim/compare/v2.2.12...v2.2.14), bringing bugfixes and improvements.

If you're still on Nim 1.6, take a look at the [version 2.0 release article](https://nim-lang.org/blog/2023/08/01/nim-v20-released.html) to see all the features you're missing.
If you've been using Nim 2.0, the [version 2.2 release article](https://nim-lang.org/blog/2024/10/02/nim-220-2010.html) shows the improvements available in Nim 2.2.







## Installing Nim 2.2.14


Check out if the package manager of your OS already ships version 2.2.14 or
install it as described [here](https://nim-lang.org/install.html).

If you have installed a previous version of Nim using `choosenim`,
getting Nim 2.2.14 is as easy as:

```bash
$ choosenim update self
$ choosenim update stable
```

**NOTE:** We recommend that you install and use the latest version of `choosenim`, v0.8.16, available in [our choosenim repo](https://github.com/nim-lang/choosenim).

Alternatively, you can download Nim 2.2.14 from
[our nightlies builds](https://github.com/nim-lang/nightlies/releases/tag/2026-10-28-version-2-2-c5c2337564e347bb8252a510c79a74817a670231).






## Security fixes

This release hardens several standard library modules against malicious input:

- `httpclient`: on a redirect that leaves the origin (scheme, host, port) of the
  requested URL, the `Authorization`, `Cookie` and `Host` headers are now dropped,
  so a server can no longer redirect the client to a host it controls and read
  its credentials. (STD-001)
- `asynchttpserver`: request bodies are now always read completely. Chunked bodies
  of methods other than POST, chunk extensions and trailer fields could previously
  be parsed as the next request on the connection, which allowed request smuggling
  behind a reverse proxy. (STD-002)
- `asynchttpserver`: requests with ambiguous body framing (both `Content-Length`
  and `Transfer-Encoding`, repeated or malformed `Content-Length`, unknown transfer
  codings, whitespace before the colon) are now rejected following RFC 9112,
  section 6.3. (STD-003)
- `net`, `asyncnet`: when a TLS client connects to an IP address, the address is
  now checked against the certificate's IP SANs. Previously any certificate signed
  by a trusted CA was accepted. (STD-004)
- `cmdline`: `parseCmdLine` (and thus `parseopt.initOptParser(string)`) no longer
  loops forever and exhausts memory on control characters. (STD-005)
- `httpclient`: CR, LF and NUL in the request target, the Host header and header
  fields now raise `ValueError` instead of allowing header and request
  injection. (STD-006)
- `xmlparser`, `htmlparser`: the nesting depth is now limited (`xmlMaxDepth`, 256,
  and `htmlMaxDepth`, 512, both `{.intdefine.}`s), so deeply nested input can no
  longer exhaust the stack. (STD-007)
- `xmltree`: the output of `$` is no longer quadratic in the nesting depth;
  indentation stops growing at 80 columns. (STD-008)
- `httpclient`: chunk sizes that overflow an `int` now raise `ProtocolError`
  instead of wrapping around and misframing the body. (STD-009)

Additionally, `asyncnet` now verifies the TLS hostname
([#26455](https://github.com/nim-lang/Nim/issues/26455)).
